# تحديث فحص مشروع مركز المأمون الطبي التشخيصي

هذا تحديث **إضافي لا يستبدل الملفات الحالية**. صُمم للمستودع المنشور في
`almamoondmcenter-glitch/almamooncenter` المبني على صفحات HTML مع GitHub Pages.

## التركيب

1. نزّل ملف ZIP وفك ضغطه.
2. ارفع المجلد `.github/workflows` والمجلد `tools` إلى جذر المستودع مع المحافظة على المسارات؛ لا تحذف أو تستبدل صفحات الموقع.
3. ارفع هذا الملف إذا رغبت.
4. افتح تبويب Actions في GitHub وشغّل `Al-Mamoon Static Site Audit`، أو انتظر تشغيله عند الدفع إلى `main`.
5. افتح ملخص التشغيل ثم artifact باسم `site-audit-report` لقراءة النتائج.

## ما الذي يختبره؟

- الروابط الداخلية المحلية وملفات الصور والسكريبتات والأنماط المشار إليها بالمسار.
- عناوين الصفحات ووسوم الوصف والـ viewport واللغة واتجاه RTL.
- نصوص alt الأساسية للصور، وروابط تبدأ من الجذر التي قد تتعطل على GitHub Pages.
- يصدر تقريرًا JSON قابلًا للمراجعة مع كل تشغيل.

## الحدود الفنية

- فحص **ثابت فقط**: لا يؤكد نجاح إرسال الحجز، أو حفظه في Supabase، أو تسجيل دخول الإدارة.
- لا يختبر حماية قواعد البيانات أو بيانات المرضى أو صحة المدفوعات.
- لا يعدّل صفحات المشروع أو البيانات أو إعدادات الإنتاج تلقائيًا.
- لم يتوفر سحب نسخة المستودع إلى البيئة الحالية ولذلك لم يُشغّل الفحص على كامل المشروع الأصلي.

## فحوص إلزامية قبل التفعيل

1. تجربة حجز اختبار ببيانات وهمية، والتحقق من وصوله إلى لوحة الإدارة وتغيّر حالته.
2. إجراء اختبار مستخدم غير مسجل للتأكد من عدم إمكانية رؤية الحجوزات والنتائج الخاصة.
3. مراجعة سياسات RLS في Supabase لجميع الجداول الحساسة، وعدم إدراج `service_role` في HTML أو JavaScript.
4. عدم وضع بيانات طبية أو هويات حقيقية في المستودع العام أو مخزن المتصفح.
5. ربط بوابة الدفع والنتائج فقط عبر خادم آمن وتكامل رسمي، مع مصادقة وصلاحيات.
6. اختبار الموقع على هواتف فعلية، واستعادة نسخة احتياطية تجريبية قبل الإطلاق الطبي.

**مهم**: اترك وضع الحجز أو النتائج الحقيقية معطلًا إلى حين إكمال اختبارات الحماية والوظائف.
